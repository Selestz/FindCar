# Источники: исследование и ограничения

Обновлено 2026-09-07. Цель — несколько первых страниц конкретного пользовательского поиска, а не выгрузка всей площадки.

## Обновление после Phase 6

Снятые и неизвестные статусы теперь исключены из текущей выдачи; история сохраняется. Drom parser версии `drom-html-2` учитывает явную отметку `bull_sold` и `OutOfStock`/`SoldOut` в структурированных данных. Устаревшая карточка каталога не возвращает подтверждённо снятое объявление в продажу: нужен активный статус на detail-странице. Отсутствие объявления в выдаче или ошибка доступа по-прежнему не доказывает снятие.

Рабочее приложение содержит только Drom и Auto.ru. Mock отключён в API/очереди и скрыт во всех пользовательских списках. Avito отложен по решению пользователя.

Добавлен локальный справочник 73 марок и 3 736 моделей из публичных каталогов обеих площадок, с раздельными URL-обозначениями и обратной нормализацией. Можно искать всю марку без модели. Пределы чтения объявлений и ограничения регионов не расширялись. Подробнее: [справочник](../backend/app/catalog/README.md).

При проверке реального Drom-запроса Москва/Panamera/до 1,9 млн на 2026-09-07 структурированный результат был снят с продажи; соседние карточки оказались рекомендациями из других городов. Они не подмешиваются в поиск Москвы. Проверка с регионом «Вся Россия» дала активные объявления с настоящими фотографиями.

## Текущее состояние Phase 4

Пользователь уточнил, что разрешение относится к чтению публичных страниц. Последовательно реализованы и проверены Drom, затем Auto.ru: обычный HTTP HTML, без входа, cookies, скрытых API и browser automation. В локальном `.env` включены `DROM_ENABLED=true` и `AUTO_RU_ENABLED=true`. Поиск через приложение сохранён как «Panamera · Drom и Auto.ru». Старый демонстрационный поиск сохранён отдельно.

Для завершения интеграции Avito нужен доступный проверяемый контракт выдачи; его отсутствие не блокирует два работающих источника.

Выводы исследования ниже описывают исходную проверку документов; оставшаяся задача Phase 4 — настроить конкретные способы доступа, endpoint и credentials. В Phase 1 все live источники имеют ACCESS_NOT_CONFIGURED, включая Drom.

## Метод и качество доказательств

Использованы поиск и чтение официальных страниц через веб-инструмент. Документация не проверялась авторизованными API-запросами: ключей/партнёрских доступов в проекте нет. Поисковая индексация страницы не доказывает разрешение на её автоматическое использование. Ошибка `Internal Error` веб-инструмента не является HTTP 403 площадки и не доказывает CAPTCHA, геоблокировку либо закрытие API.

Не исследовали обход защиты, не использовали неофициальные ключи/мобильные API, не загружали массивы объявлений и фотографий. Доступность SSR HTML, embedded JSON и конкретных поисковых параметров в этом окружении не подтверждена. Утверждений о проверенных CSS selectors или работающих внутренних endpoint здесь нет.

## Avito Авто

Официальные адреса, которые пытались прочитать:

- [Каталог API](https://developers.avito.ru/api-catalog).
- [Core API documentation](https://developers.avito.ru/api-catalog/core/documentation).
- [Условия использования](https://www.avito.ru/legal/rules/terms-of-use).
- [robots.txt](https://www.avito.ru/robots.txt).

Все четыре чтения дали `Internal Error` веб-инструмента; содержимое и HTTP-статус сервера Avito не получены. Поэтому не утверждаем ни наличие подходящего public search API, ни его отсутствие. Описания сторонних scraper-сервисов не используем как доказательство официальной возможности или разрешения.

Порядок дальнейшей проверки: восстановить обычный доступ к официальной документации; найти документированный метод поиска именно чужих автомобильных объявлений; проверить scope аккаунта и условия; при отсутствии подходящего метода уточнить официальный интеграционный доступ. HTML или серверный JSON рассматриваются только после проверки допустимости и на малом объёме. Browser automation не является способом обойти нерешённый вопрос доступа.

До этого capabilities всех фильтров unverified. Нельзя обещать generation, owners, radius, публикацию или фотографии только потому, что эти поля иногда есть в пользовательском интерфейсе.

## Auto.ru

Во [введении в официальный API](https://yandex.ru/dev/autoru/doc/ru/) описаны статистические и справочные данные, включая структуру каталога и количество активных объявлений. Это полезно для справочников, но само по себе не подтверждает выдачу карточек по всему рынку.

Проверенный [GET /user/offers/{category}](https://yandex.ru/dev/autoru/doc/ru/reference/user-offers-category) возвращает список объявлений пользователя и находится в разделе управления объявлениями дилера. Он содержит фильтры и пагинацию, но его нельзя использовать как доказанный общий metasearch endpoint. Наличие параметра price_to не меняет scope метода.

В [официальной справке об API](https://yandex.ru/support/autoru-legal/ru/api) указано, что для работы нужен авторизационный токен, а при обращении за ним следует назвать требуемый ресурс. Для проекта подходящий scope ещё не подтверждён; никаких обращений в поддержку от имени пользователя не отправляли.

Попытки чтения `https://auto.ru/support/autoru-legal/ru/terms`, `https://auto.ru/legal/agreement/` и переходов к разделам доступа из API docs дали Internal Error. Актуальные условия альтернативного чтения HTML/JSON не установлены. Не переносим условия дилерского кабинета на доступ к объявлениям других продавцов.

Решение: сначала документированный партнёрский/read search доступ, если доступен для этой задачи. Пока не подтверждены подходящий ресурс, scopes и допустимое использование данных, live adapter отключён. JSON из веб-приложения не считается публичным API без дополнительных оснований. Статус AUTH_REQUIRED применяется только когда подходящий механизм уже настроен, но ему не хватает авторизации; начальное состояние — ACCESS_NOT_CONFIGURED.

## Drom

Официальная [инструкция autoload](https://www.drom.ru/misc/autoload/) описывает автоматическую публикацию данных из XML-файла продавца на Drom. Направление обмена — к площадке; это не API получения общей поисковой выдачи.

[Правила портала](https://www.drom.ru/about/reprint/), показанная версия от 22.12.2025, распространяются в том числе на auto.drom.ru. Пункты 5–6 требуют предварительного письменного разрешения на автоматизированное извлечение/сбор; пункт 3 о личном использовании не принимаем за разрешение такого сбора. Условия также затрагивают фото и кэширование. Это изложение проверенного текста правил, а не заключение о применимости права к любому возможному сценарию.

На момент исходного исследования сведений о разрешении не было; затем пользователь подтвердил его наличие. Подходящий официальный read/search API не найден в проверенных документах. Реальный adapter и thumbnail cache относятся к Phase 4: отдельно фиксируем конкретный endpoint/HTML contract, покрытие фильтров, pagination, изображения и разрешённую частоту. Сейчас используется синтетический mock.

## Порядок выбора транспорта

1. Официальный API/интеграция: подтвердить, что возвращает нужную поисковую выдачу, а не собственные объявления/статистику/публикацию.
2. Серверный JSON: подтвердить допустимость, scope, механизм авторизации и стабильность; данные, видимые браузеру, не автоматически являются поддерживаемым API.
3. HTML: только при допустимом доступе; сначала schema/page identity и структурированные данные, затем устойчивые элементы DOM. Сеть, parsing и normalization — отдельные файлы.
4. Browser automation: только при доказанной необходимости для разрешённого механизма. CAPTCHA и запреты не решаются автоматизацией браузера.

Ни robots.txt, ни маленький объём, ни приватность сервиса сами по себе не подтверждают разрешение. Начальные лимиты в architecture.md — собственные пределы проекта; если источник разрешит меньшую нагрузку, применяются более строгие значения.

## Состояния и fixtures

Configuration state (`disabled|enabled`) отделён от runtime health. Disabled не выглядит как «0 найденных машин» и не расходует запросы. Для подключённого источника: OK, RATE_LIMITED с Retry-After, AUTH_REQUIRED, SOURCE_UNAVAILABLE, PARSER_ERROR; причиной недоступности может быть ACCESS_NOT_CONFIGURED/ACCESS_NOT_PERMITTED. Для UI сохраняются время последнего успеха и неполнота результатов.

После получения допустимого доступа для каждого источника нужны offline fixtures:

- непустая выдача, настоящая пустая выдача, последняя/следующая страница;
- detail ACTIVE, явное REMOVED, неполные поля;
- CAPTCHA/страница входа, 429/503, неожиданный JSON schema/HTML;
- отсутствующая цена, владельцы, поколение, описание и фото;
- разная валюта/единицы, изменение цены, недоступная картинка.

Fixtures хранятся в `backend/tests/fixtures/<source>/`; рядом manifest: synthetic или разрешённый captured, дата, тип страницы, обезличенный URL, способ/основание получения, parser_version и ожидаемый outcome. Удалить cookies/tokens/телефоны/email/лишние данные продавца. Реальные HTML и mock fixtures никогда не маркируются одинаково. Сейчас captured fixtures не создавались.

## Условия подключения в Phase 4

Подходящий доступ подтверждён; источник включается явно; capabilities проверены fixture-тестами; ссылки ведут на исходные карточки; парсер отличает пустую выдачу от ошибки; лимиты/ошибки/partial проверены; image hosts и условия thumbnails документированы; минимум один разрешённый smoke-запрос выполнен из окружения запуска. Отчёт содержит дату, метод и фактический результат. Оставшиеся источники могут быть недоступны без остановки продукта.

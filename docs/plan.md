## Phase 1 — Core и минимальный vertical slice

Подробные команды и ограничения — в README. Compose config валиден; фактический запуск контейнеров на этой машине не проверен из-за недоступной аппаратной виртуализации Docker. Следующий продуктовый этап — Phase 2.

1. Создать структуру из architecture.md, Python 3.12+, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL; зафиксировать зависимости. Добавить `.gitignore`, `.env.example`, Compose, backend/worker Dockerfile. Не класть секреты в примеры.
2. Реализовать первоначальную миграцию: пользователи, сессии, поиски, задания, объявления, кластеры, связи, snapshots, события и ограничения из database.md. Таблицы matching допустимо добавить отдельной миграцией Phase 2.
3. Добавить bootstrap admin через CLI, вход/выход, проверку владельца каждого пользовательского ресурса. Открытой регистрации нет.
4. Реализовать DTO и SourceAdapter; MockSourceAdapter с фиксированными часами и сценариями, включая ошибки источника. Его source=`mock`, подпись в API/UI — «Демонстрационные данные».
5. Реализовать SavedSearch → job → source.search → normalize → upsert Listing → пользовательский VehicleCluster → результаты API. Минимальный worker исполняет задания сейчас; периодический мониторинг появляется в Phase 5.
6. Добавить минимальную функциональную страницу результатов. Полный дизайн и остальные пользовательские экраны — Phase 3. В Phase 1 новые объявления пока получают отдельные кластеры, полноценная склейка — Phase 2.

Проверка этапа: unit-тесты моделей и нормализации; integration-тест с настоящим PostgreSQL для идемпотентного ingestion, изоляции пользователей, snapshot/event; upgrade миграций на чистой БД; lint/typecheck; запуск Compose и проверка сохранения поиска и результатов в браузере. ## Решения, которые нельзя потерять при реализации

- Нет полного обхода площадок и обещаний полной выдачи или realtime.
- Пропажа из первых страниц не равна REMOVED.
- Неизвестное значение фильтра не считается подтверждённым совпадением.
- Нет auto merge без сильного индивидуализирующего сигнала; решения пользователя приоритетны.
- Неполные ответы и ошибки источника не удаляют сохранённые данные.
- Персональные поиски, заметки и решения о дублях не видны другим пользователям.
- Никаких CAPTCHA bypass, spoofing, proxy rotation, доступа к чужим аккаунтам или скрытых API по скопированным ключам.
